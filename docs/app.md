# RootMate: заметки по приложению (для доработок)

Приложение для ТВ на Android TV (Changhong/Tuvio, MT5889). Делает то, что в `guide.md` приходится делать руками: включает UART, ставит Magisk и патчит boot-образ прямо на ТВ, без ПК. Версия 1.0, пакет `com.tobirg.rootmate`, minSdk 26, targetSdk 34, Kotlin, Material Components, без сторонних библиотек.

## Структура

| Файл | Что делает |
|---|---|
| `app/src/main/java/com/tobirg/rootmate/MainActivity.kt` | Весь основной экран и вся логика: кнопки, скачивание и установка Magisk, патч образов, лог, прогресс |
| `.../FilePickerActivity.kt` | Свой файлпикер на `java.io.File` (без SAF). Стартует со списка накопителей, показывает папки и `.img` |
| `.../PermissionsActivity.kt` | Экран двух разрешений: «Доступ ко всем файлам» и «Установка неизвестных приложений» |
| `.../TvFocus.kt` | Подсветка фокуса для пульта (белая рамка поверх кнопки, приглушение недоступных) |
| `res/layout/`, `res/layout-land/activity_main.xml` | Две раскладки главного экрана. Основная — альбомная (панель кнопок слева, лог справа 1:1) |
| `res/values/strings.xml`, `res/values-en/strings.xml` | Все тексты. Русский основной, английский полный. В коде нет русских строк, всё через `getString(R.string...)` |
| `res/drawable-nodpi/` | `ic_launcher_foreground.png`, `tv_banner.png` (генерировались из `docs/icon.png`) |
| `.github/workflows/android.yml` | Сборка в GitHub Actions, артефакт `RootMate`, релиз по тегу `v*` |

Сборка локально не настроена (нет Gradle wrapper): проверка только через CI.

## Главный экран

Блоки сверху вниз:
1. **Подготовка**: «Открыть инженерное меню» с подписью «Включение UART» (`com.homwee.factory/.FactoryActivity`, страница 4, дальше переключатель вручную: Design Mode → Uart → On; прямого вызова UART через HIDL нет: он не работал), «Скачать и установить Magisk» + строка со статусом установленной версии.
2. **Переключатель режимов** «Полуавтомат» / «Ручной» (`MaterialButtonToggleGroup`, при запуске всегда полуавтомат, при пересоздании activity режим сохраняется).
   - **Полуавтомат**: строка этапа («Шаг 1 из 4, разведка: …», «Бэкап завершён: … Следующий шаг — …») и главная кнопка мастера (см. ниже). Записи лога идут без пустых строк. Диалог MBOOT (`res/layout/dialog_mboot.xml`): нумерованные шаги, команды в отдельном моноширинном блоке, для check + flash ниже порядок запуска и совет про `Invalid FAT entry`; на ТВ диалог шириной 70% экрана, чтобы всё помещалось без прокрутки (D-pad её не прокручивает). Кнопок копирования команд нет.
   - **Ручной**: только «Выберите один из способов»: строка активного слота, автопатч оригинального образа (слева) и фикс уже пропатченного Magisk-образа (справа). Окно «Продолжить?» в этом режиме не всплывает, скрипты для MBOOT не создаются и сообщений о них нет (`fullPatch(withScripts = false)`).
3. **Удалить RootMate**: в обоих режимах, сразу системный диалог удаления (свой диалог убран).

Пока идёт долгая операция (`runBusy`), все кнопки заблокированы, экран не гаснет, под логом виден прогресс. «Назад» в это время показывает предупреждение.

## Magisk

- Версия берётся без `api.github.com` (там лимит 403): `github.com/topjohnwu/Magisk/releases/latest` отдаёт редирект на `/tag/vX.Y`, имя файла `Magisk-vX.Y.apk`, ссылка `/releases/download/<tag>/<имя>`. Список файлов релиза (`expanded_assets/<tag>`) пробуется первым, стандартное имя запасное.
- Если установленная версия (`versionName`) равна тегу без `v`, скачивание и установка пропускаются.
- Скачанный APK лежит в `cacheDir/Magisk-vX.Y.apk`. Если он уже есть и открывается как APK, повторно не скачивается. Скачивание идёт в `.part`, потом переименование.
- Установка через `PackageInstaller` (запасной вариант `ACTION_VIEW`), результат ловит динамический `BroadcastReceiver`.
- Magisk считается установленным, если есть пакет `com.topjohnwu.magisk` и `libmagiskboot.so` в его `nativeLibraryDir`.

## Активный слот

Над кнопками патча строка со слотом из `ro.boot.slot_suffix` (`SystemProperties.get` по рефлексии, запасной вариант `getprop`). Если выбранный файл называется `BOOT_A`/`BOOT_B` и не совпадает со слотом, после патча в конец лога пишется крупное жёлтое предупреждение (патч не блокируется). Если свойство недоступно, показывается «слот не определён».

## Патч образов

Результат всегда сохраняется рядом с выбранным файлом, существующие файлы не перезаписываются (`_2`, `_3`...). Запись идёт через `.part` с переименованием. Перед стартом проверяются права на запись и свободное место (на накопителе и во внутренней памяти). Рабочие папки в `filesDir` удаляются всегда.

**Автопатч** (`fullPatch`, кнопка «Выбрать BOOT_*.IMG», образ оригинальный, не пропатченный):
1. Из установленного Magisk берутся `assets/boot_patch.sh`, `util_functions.sh`, бинарники `magisk`, `magiskinit`, `magiskboot`, `init-ld`.
2. Бинарники подключаются **симлинками** на `nativeLibraryDir` Magisk: Android запрещает запускать только что записанные в данные приложения файлы (W^X), а библиотеки Magisk исключены.
3. `boot_patch.sh` запускается с `BOOTMODE=true` (иначе скрипт не определит, что система загружена, из-за видимости процессов). Переменная `LEGACYSAR` не используется: на этом ядре она ничего не меняла.
4. Применяется фикс `skip_initramfs` → `skip_initramfz` в `magiskinit` (см. ниже).

**Ручной фикс** (`patch`, кнопка «Выбрать magisk_patched-*.img», образ уже пропатчен Magisk): только фикс ниже, результат `*_skipfix.img`.

**Фикс** (`applySkipInitramfsFix`): `magiskboot unpack` → извлечь `init` из `ramdisk.cpio` → заменить все `skip_initramfs` на `skip_initramfz` (та же длина) → вернуть `init` → `repack`. Если строки в `init` нет, это не образ Magisk (`magiskboot` сам этого не проверяет), патч прерывается с ошибкой и ничего не сохраняется. Число замен зависит от версии Magisk (при 28 было 2, при 31.1 одна).

## Разрешения

- `MANAGE_EXTERNAL_STORAGE`: свой файлпикер без SAF (на прошивке SAF-провайдер сторонний, Fluffy).
- `REQUEST_INSTALL_PACKAGES`: установка Magisk.
- `REQUEST_DELETE_PACKAGES`: самоудаление.
- Кнопки без нужного разрешения приглушены, нажатие открывает экран разрешений. Он также открывается один раз при первом запуске.

## Интерфейс и пульт

- ТВ-приложение: `LEANBACK_LAUNCHER`, `leanback` и `touchscreen` как необязательные, баннер `tv_banner`.
- Фокус рисуется внутри границ кнопки (иначе родитель его обрезает). У Material-кнопок обнулены `insetTop/Bottom`.
- Отступы кнопок нужно задавать через `paddingLeft/Right`, а не `paddingStart/End`: иначе их перебивает стиль Material.
- Ширина одиночных кнопок 2/3 строки: горизонтальный `LinearLayout` с `weightSum=3` и кнопкой `weight=2`.
- Лог доступен для фокуса (прокрутка пультом), рамка рисуется на карточке `logCard`, а не на прокручиваемом `ScrollView`. Автоскролл делается через `scrollTo`, чтобы не забирать фокус с кнопок.
- Стиль сообщений: действия от первого лица («Открываю…», «Собираю…»), обращение к пользователю на «вы».

## Сборка и релиз

- Имя файла: `RootMate-<versionName>.apk` (задаётся в `app/build.gradle.kts`). Версия 1.0 (`versionCode = 3`: выше прежних сборок 1.1, чтобы ставилась поверх); при выпуске новой поднимать оба значения.
- CI собирает на каждый push в `main`, артефакт `RootMate`. Релиз с APK публикуется при пуше тега `v*`.
- Подпись постоянным ключом из секретов GitHub (`SIGNING_KEYSTORE_B64`, `SIGNING_PASSWORD`, alias `rootmate`), поэтому новые версии ставятся поверх старых. Локально без этих переменных используется debug-ключ. Копия keystore и пароль хранятся у владельца вне репозитория: потеряете ключ, пользователям придётся удалять приложение перед обновлением. Сборки до этой правки (1.0) подписаны случайными ключами CI, поэтому на них нужно удалить старую версию вручную один раз.
- Имя пакета менялось (было другое), старую установку нужно удалить вручную.

## Скрипты для MBOOT

После `fullPatch` (когда известен оригинальный образ) `MainActivity.generateMbootScripts` вызывает `MbootScripts.generate`
(`MbootScripts.kt`) и пишет в корень внешнего накопителя `flash.txt`, `check.txt` (то же без записи) и `rollback.txt`.
Шаблоны: `assets/mboot/flash.tpl` и `rollback.tpl`. Правила: строка `@W ` остаётся только в реальном скрипте (пишет в eMMC),
`@D ` только в сухом прогоне; плейсхолдеры `{{SLOT}}`, `{{SLOTHEX}}`, `{{ORIG}}`, `{{NEW}}`, `{{CRC_ORIG}}`, `{{CRC_NEW}}`,
`{{WIPE_CMD}}`, `{{WHEN}}`. Слот берётся из `ro.boot.slot_suffix`, сброс данных отключается, если `ro.boot.verifiedbootstate` = orange.
Скрипты не создаются, если образы не 32505856 байт, результат не на внешнем накопителе, имя образа не совпадает со слотом
или в пути не только латиница, цифры и `. _ - /`.
udstar выполняет файл линейно: нет `if/for`, `$var` не раскрывается (только `${var}`), любая ошибка команды останавливает скрипт,
поэтому «условия» в шаблонах сделаны через `cmp`. Тот же рендер для проверки на ТВ: `uart_dump/tools/render_scripts.py`
(держите правила в обоих местах одинаковыми).

### Мастер этапов, скрипты и перезагрузка (Wizard, MbootScripts)

В приложении и шаблонах нет значений, связанных с конкретным ТВ. Всё лежит в корне флешки (fatwrite в MBOOT пишет только в корень и только
имена до 12 символов; `fatload` и `udstar` умеют подпапки, но папка ничего не даёт).

**Этапы** (`Wizard.detect`, по файлам на флешке; показывается строкой этапа и главной кнопкой): `FRESH` -> `PROBE_READY` -> `PROBE_DONE`
(`PROBE.OK` + `PTABLE.BIN` + `ENV.TXT`) -> `BACKUP_READY` -> `BACKUP_DONE`/`BACKUP_BAD` (маркер из строки `# Marker:` в `backup.txt`; образы
проверяются: размер = размеру раздела из таблицы, CRC32 файла = значению в `*.CRC`, которое посчитал MBOOT по данным eMMC) -> `PATCHED`
(`flash.txt`, `check.txt`, `rollback.txt`) -> `FLASH_DONE` (`FLASH.OK`, переживает сброс данных). Если приложение запущено в состоянии
`PROBE_DONE` или `BACKUP_DONE`, оно само спрашивает «Продолжить?». Этап обновляется после каждой операции и сразу при подключении или
отключении флешки (`ACTION_MEDIA_*`). В ручном режиме этап не проверяется; CRC32 образов бэкапа кэшируется по размеру и времени изменения файла.

**Флешка выбирается один раз** (`Wizard.detect`, id = имя папки в `/storage`, то есть серийный номер тома FAT, хранится в SharedPreferences
`wizard/drive_id`). Без сохранённого выбора флешка берётся только однозначно: единственная подключённая или единственная с файлами RootMate;
иначе этап `CHOOSE_DRIVE` и список. Выбранная флешка не подключена (или её переформатировали: серийный номер меняется) — `DRIVE_MISSING`,
одной кнопкой можно перейти на вставленную. При нескольких флешках под этапом есть «Сменить флешку». Под этапом строка «Флешка: метка (id), объём, ФС».
Перед работой проверяется, что MBOOT её прочитает (`/proc/self/mounts`, строка `/dev/block/vold/public:8,N /mnt/media_rw/<id> <fs>`):
файловая система `vfat` и раздел 1 или вся флешка без таблицы разделов (U-Boot считает её разделом 1); иначе `BAD_DRIVE` с объяснением.
Без разрешения «Доступ ко всем файлам» — `NO_PERMISSION` (раньше это выглядело как «флешка не найдена»). В какой USB-порт вставлять флешку,
говорит инструкция: `usb start 1` опрашивает только порт 1, из Android порт не узнать.

**Скрипты.** `probe.txt` (статичный): `mmc read` первых 32 КиБ eMMC (`PTABLE.BIN`), `env export -t` (`ENV.TXT`), адрес буфера `${MI_KERNEL_POOL2_ADR}`
подставляет сам MBOOT (в файле для udstar работает `${имя}`, не `$имя`). `MbootScripts.loadLayout` разбирает `PTABLE.BIN` (записи по 512 байт с 0x200:
`u32 0x5840`, `u32 ?`, `u32 start`, `u32 length` в блоках по 512 Б, имя с 0x10) и `ENV.TXT`; из них `writeBackup`/`generate` берут список разделов,
размеры, имена файлов (8.3, индекс `_2`…`_9`, чтобы не затереть бэкап, и отдельный маркер `BACKUP_n.OK`) и три буфера A/B/C внутри пула (каждый размером
с самый большой образ, до 1 МиБ вверх). `flash.tpl`/`rollback.tpl` берут размер образа из записи `boot_<слот>`. Нет файлов, нечитаемы или образ не
помещается в пул: скрипт не создаётся, приложение говорит почему. Каждый скрипт перед `reset` делает `usb stop` и пишет свой маркер.

**Перезагрузка без root** (`AdbLocal`): кнопка «Перезагрузить ТВ» в диалоге MBOOT вызывает `sync`, подключается к `127.0.0.1:5555` (на этом ТВ adbd слушает
tcp 5555, как только включена «Отладка по USB»: `service.adb.tcp.port=5555`), проходит рукопожатие adb (CNXN, AUTH с подписью токена RSA-2048 и своим
публичным ключом) и открывает сервис `reboot:`. Первый раз ТВ показывает «Отладка по USB» с отпечатком ключа, после «Всегда разрешать» запрос не повторяется.
Если adb недоступен, открываются штатные настройки с подсказкой «Система» → «Перезагрузить» → подтвердить (штатное окно TvSettings
`about.RebootConfirmFragment`; напрямую его не открыть: у фрагмента нет своей activity, `REBOOT`/`SHUTDOWN` — signature-разрешения, экспортированный
`DeviceSettingBroadcastReceiver` закрыт `READ_PRIVILEGED_PHONE_STATE`).

**Режим разработчика и adb** (`AdbLocal.status`, экран «Разрешения», третья карточка): `Settings.Global.DEVELOPMENT_SETTINGS_ENABLED`, `ADB_ENABLED` и
проверка порта 5555. Кнопка открывает «Об устройстве» (`ACTION_DEVICE_INFO_SETTINGS`, там 7 раз «Сборка») или «Для разработчиков»
(`ACTION_APPLICATION_DEVELOPMENT_SETTINGS`, «Отладка по USB») и показывает тост, что нажать. Выделить конкретный пункт нельзя: TvSettings этой прошивки
не поддерживает `:settings:fragment_args_key`. Экран разрешений открывается сам при первом запуске, если не хватает любого из трёх.

**Агенты** (`Agent.kt`, [agent.md](agent.md), `scripts/agent/`): `AgentReceiver` (exported, `android:permission="android.permission.DUMP"`: есть у adb shell,
нет у обычных приложений) принимает `am broadcast ... --es cmd <status|next|choose|patch|fix|log>` и отвечает JSON в result data. Команды выполняет открытая
MainActivity (`Agent.host`, launchMode singleTask) в любом режиме; с первой команды диалоги не показываются, экран не гаснет, команды пишутся в лог;
нажатие на пульте (`onUserInteraction`) возвращает обычное поведение. `next` = главная кнопка мастера без диалогов, `patch`/`fix` = ручной режим по пути.
`scripts/agent/rootmate.py` (обёртка над am broadcast, исправляет пути, испорченные Git Bash) и `scripts/agent/mboot.py` (консоль MBOOT через pyserial:
`catch`, `udstar <скрипт>` с проверкой маркера успеха, `reset`). Проверено на ТВ: probe → backup → patch → check.txt целиком через эти скрипты.

**Не удалять файлы, записанные MBOOT** (`Wizard.retire` переименовывает в `*.oldN`): MBOOT пишет конец цепочки в FAT как `0xFFFFFFFF`, и Linux при повторном
использовании этих кластеров сохраняет старшие 4 бита; драйвер FAT в MBOOT их не маскирует и отвечает `Invalid FAT entry`. Так же объясняется порча
файлов, которые MBOOT пересоздаёт (`file exist, and will be recreate`). Проверено разбором таблицы FAT с флешки (дамп через `usb read`).

Проверено на ТВ: probe -> backup -> патч -> `check.txt` по файлам, собранным приложением; распознавание этапов. Переход в «Система» → «Перезагрузить» проверен на ТВ (Android 11, Google TV).
