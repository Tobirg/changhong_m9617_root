# Восстановление и диагностика

🇬🇧 [English version](recovery.en.md)

Эта страница относится к исследованному CHiQ/MT5889 с MStar MBOOT. Главный принцип — **до любых записей сделать BOOT_A.IMG/BOOT_B.IMG, проверить их размер и хранить на ПК**. Неправильное восстановление раздела может ухудшить ситуацию.

## 1. Android не загружается после записи MAGISK.IMG

Если доступна интерактивная консоль MBOOT, верните **исходный boot именно активного слота**. Ниже показан пример **_a**, USB **0:1**, размер раздела **0x1F00000**. Все три параметра надо перепроверить.

Перенесите исходный **BOOT_A.IMG** обратно на FAT32-флешку.

~~~text
usb start 1
usb storage
fatls usb 0:1
mmc part
mmc look boot_a
fatload usb 0:1 0x25000000 BOOT_A.IMG
crc32 0x25000000 0x1F00000
mmc write.p 0x25000000 boot_a 0x1F00000 0
mmc read.p 0x25000000 boot_a 0x1F00000
crc32 0x25000000 0x1F00000
reset
~~~

**Перед записью** проверьте, что размер загруженного файла ровно совпадает с размером раздела, первоначальная резервная копия читаема и CRC до/после записи одинаковы. Если текущий активный слот **_b**, восстановите **BOOT_B.IMG в boot_b**. Не восстанавливайте чужую прошивку или образ из другого слота по умолчанию.

Восстановление boot **не возвращает удалённые при factory reset пользовательские данные**.

## 2. Red state / ошибка шифрования / циклическая загрузка

В эксперименте после изменения Verified Boot state обнаруживалась ошибка:

~~~text
vold ... begin failed, code -33 INVALID_KEY_BLOB
~~~

Это указывало на несовместимость прежнего ключа **/metadata** с новым состоянием загрузки. Исправление: запуск штатного Android Recovery и **Wipe data/factory reset**, после резервного копирования всех доступных пользовательских данных.

В MBOOT:

~~~text
panel_pre_init
readKL recovery
bootKL
~~~

На данном телевизоре **Recovery запускается, но меню не управляется пультом**. При этом Android Recovery может автоматически обрабатывать запрос `--wipe_data` из загрузочного сообщения BCB в разделе `misc`.

В родственных исходниках MStar MBOOT запрос создаётся командой `recovery_wipe_partition data`. На исследованном MT5889 команда присутствует; её `help` показывает только описание без аргументов, но код родственной MStar-сборки читает `argv[1]` и требует `data` либо `cache`. Без аргумента не выполнять. Справка:

~~~text
help recovery_wipe_partition
~~~

**После резервного копирования** можно попробовать поставить запрос на полный сброс, затем перезагрузиться (исполнение на этой сборке ещё не проверено):

~~~text
recovery_wipe_partition data
reset
~~~

После этого загрузите Recovery (через стандартный перезапуск, если он подхватывает BCB, либо вручную через `panel_pre_init`, `readKL recovery`, `bootKL`). **Подтверждения выполнения этой команды именно на текущей сборке пока нет.** Альтернатива при работающем Android и root — создать `/cache/recovery/command` с единственной строкой `--wipe_data`, затем загрузить Recovery. Ранее такой вариант сработал.

После сброса на исследованной системе форматировались **/data, /cache и /metadata**, а Android стартовал в состоянии **orange**. Повторное прошивание Magisk **не** заменяет сброс. Не стирайте эти разделы вручную, пока не подтверждена возможность автоматического форматирования файловых систем.

Если Recovery не стартует, первым делом проверьте **исходный boot**, активный слот, UART-лог и состояние MBOOT. Не пишите наугад в **misc**, **vbmeta**, **MBOOT**, **dtbo**.

## 3. Magisk не выдаёт root, но Android загружается

Проверьте:

~~~powershell
adb shell getprop ro.boot.slot_suffix
adb shell getprop ro.boot.verifiedbootstate
adb shell getprop sys.boot_completed
adb shell "/debug_ramdisk/su -c id"
~~~

Возможные причины: **прошит не тот слот** (сверьте `ro.boot.slot_suffix` с тем, в какой раздел вы писали), запущен другой boot-слот, Magisk не завершил дополнительную настройку, **magiskinit** ошибочно обработал **skip_initramfs**, образ сделан из другой версии прошивки. Не используйте **Direct Install** для «починки» вслепую. Порядок действий: [полное руководство](guide.md).

## 4. RootMate пишет «нет строки skip_initramfs» или другую ошибку

- **«В /init образа нет строки skip_initramfs: это не образ, пропатченный Magisk»**: вы выбрали кнопкой «Только фикс» оригинальный `BOOT_*.IMG`. Для оригинального образа используйте левую кнопку **Выбрать BOOT_\*.IMG** (автопатч), для образа, уже пропатченного Magisk, правую. Если образ пропатчен другой версией Magisk, где строки нет, фикс не нужен или не поддерживается. Файл в любом случае **не создаётся**.
- **«Magisk не установлен (или не найден magiskboot)»**: нажмите **Скачать и установить Magisk**.
- **«Папка недоступна для записи» / «мало места»**: флешка только для чтения, переполнена или не FAT32. Освободите место (нужно около 100 МБ на флешке и во внутренней памяти).
- **Кнопки тусклые, при нажатии открываются разрешения**: выдайте «Доступ ко всем файлам» и «Установка неизвестных приложений».
- Образ не создаётся без видимой причины: прочитайте вывод `boot_patch.sh` в логе справа. Не пытайтесь прошивать несуществующий или неполный результат.

## 5. Флешка не видна или файл не читается

~~~text
usb start 1
usb storage
usb tree
usb dev
usb part
fatls usb 0:1
~~~

**0:1** — только пример. Номер накопителя смотрите в **usb storage**. Используйте FAT32 + MBR, проверьте порт, питание и целостность USB. Команда **usb start 1** не означает, что диск имеет номер **1**.

## 6. Ошибки размера, CRC, раздела

- Не выполнять **mmc write.p**, пока не подтверждены имя раздела и размер.
- **0x1F00000** — размер boot для исследованного устройства, а не обязательный размер любого MT5889.
- Пропатченный образ RootMate сохраняет исходную длину (32505856 байт). Если **fatload** загрузила не столько байт, сколько ожидалось, прервите операцию.
- При несоответствии CRC после обратного чтения сразу восстановите **оригинальный** образ из бэкапа, не перезагружаясь.
- **0x25000000** — адрес RAM в подтверждённой конфигурации; сверять с **printenv bootcmd**, **bdinfo**, **get_mmap**. Не копировать произвольные адреса из чужих инструкций.

## 7. MBOOT не стартует или нет UART

Восстановление boot через **mmc write.p** возможно **только если консоль MBOOT всё ещё работает**. Если повреждён сам MBOOT, таблица разделов, память eMMC или питание устройства, эта инструкция недостаточна: потребуется отдельная диагностика платы, а иногда программатор. **Не пытайтесь компенсировать отсутствие MBOOT случайными командами записи.**

Для UART на исследованном CHiQ/MT5889: HDMI **2 = TX ТВ**, **14 = RX ТВ**, **8 = GND**, адаптер **3,3 В TTL**, **115200 8N1**, **без VCC**. Не подключать кабель HDMI и UART-провода в один порт одновременно.
