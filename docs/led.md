# Индикатор питания: модуль ядра ledctl

Модуль Tuvio power LED control (`ledctl.ko`, версия 1.0) сделан для телевизоров Tuvio TO48/55/65UFGCV5 (MT5889). Экран «Индикатор питания» в RootMate (нужен root) управляет их светодиодом питания без изменения boot-образа:

| | Режимы | Яркость | Скорость мигания |
| --- | --- | --- | --- |
| **В режиме сна** | не горит / горит / мигает | 5–100 % для «горит»; мигание всегда на полной | ×0,75–×4 |
| **В работе** | не горит (как в прошивке) / горит / мигает | 5–100 % для «горит» и «мигает» | ×0,75–×4 |

«Не горит» в работе — это состояние из прошивки: она сама держит индикатор тёмным, модуль не вмешивается. Скорость ×1 — примерно одна вспышка в секунду. Настройки применяются сразу и сохраняются на следующие загрузки, поэтому кнопки «Готово» нет.

Почему во сне мигание не бывает тусклым: пока процессор спит, мигает сам ШИМ. Он один, и его можно настроить либо медленным (мигает на полной яркости), либо быстрым (горит ровно, яркость по скважности), но не тем и другим сразу. В работе процессор не спит, поэтому модуль мигает программно (поток ядра `ledctl_blink`): чередует тусклое свечение и темноту.

Кнопка «Индикатор питания» появляется на главном экране только там, где модуль действительно работает. При установленном Magisk приложение один раз делает пробную загрузку `insmod ledctl.ko probe_only=1`: ядро проверяет CRC, модуль выполняет все свои проверки, ничего не пишет и завершается с `ECANCELED` («Operation canceled»). Только такой ответ (или уже загруженный ledctl) показывает кнопку. Ответ запоминается для этой сборки ядра (`uname -r` и `-v`) и этой сборки модуля (по контрольной сумме `ledctl.ko`). Пока root не выдан, проба повторяется не чаще одного раза за открытие экрана. «Удалить модуль» выгружает его, и индикатор возвращается к заводскому поведению.

## Как это работает

Индикатор подключён к каналу PM PWM. В ядре его ведёт драйвер `pwm_backlight`. При старте драйвер один раз читает из device tree свойства `led-pwm-control-{resume,suspend}-{period,duty,div,polarity}` и хранит их в своей структуре. Перед сном (`pwm_backlight_suspend`) и после пробуждения (`pwm_backlight_resume`) он программирует ими ШИМ через `MDrv_PM_PWM_*_Ex`. Заводское dtbo задаёт для сна полярность 1, поэтому в сне индикатор горит.

`ledctl.ko` меняет значения для сна прямо в памяти драйвера: перед каждым засыпанием (PM-notifier) и при изменении настроек. Пока экран выключен, туда же, в значения для пробуждения, записывается режим сна, поэтому при фоновых пробуждениях (Doze, сеть) индикатор выглядит так же, как во сне. После включения экрана значения для пробуждения возвращаются заводские.

Экран выключен, а процессор ещё работает: после выключения ТВ не засыпает несколько секунд (во время очистки OLED-панели Off-RS — до ~6 минут), и периодически просыпается сам. В это время индикатором управляет `mik.ko` по своей таблице стадий из board ini (`BOARD_LED_STAGE_*`). Через 5 с после выключения его таймер (`_mi_pm_led_turnoff_timer_cb_task`), а затем его suspend-callback ставят стадию `STANDBY_ENTER` в состоянии 1: скважность = период, полярность инвертирована, то есть индикатор горит на 100% независимо от `DUTY` в ini. Поэтому модуль ставит ftrace-перехват на `MDrv_PM_PWM_Polarity_Ex` (kprobes в этом ядре нет): если её вызвал код `mik.ko`, а экран выключен, поток `ledctl_fix` через 1–2 мс снова выставляет режим сна. При включённом экране он так же восстанавливает заданный режим «в работе» (`on_led` ≥ 0). Состояние перехвата видно в строке `hook:` параметра `info`. Остаётся короткая вспышка в момент пробуждения из сна: её даёт прошивка PM до того, как ядро делает первую запись в ШИМ, ядро на неё не влияет.

Режим «в работе» модуль задаёт сам, только пока экран включён. После включения экрана сервис ТВ (`mi_pm_SetLedControl` в `mik.ko`) примерно через секунду перепрограммирует индикатор по своей таблице из board ini. Поэтому `watch.sh` ждёт в `logcat` события `screen_toggled` и пишет в параметр `screen_on`: после `1` несколько раз подряд (0,5–8 с), после `0` один раз. При `screen_on=0` модуль останавливает мигание и сразу показывает режим сна. Перед засыпанием программное мигание тоже останавливается, чтобы после драйвера никто не перепрограммировал ШИМ.

Замеры на Tuvio TO55UFGCV5: заводской делитель `0xff` даёт медленный ШИМ (около 1 Гц), поэтому половинная скважность мигает. С делителем 0 ШИМ быстрый, и яркость пропорциональна скважности. Скорость мигания во сне меняется периодом ШИМ (16 бит), поэтому медленнее ×0,72 не бывает.

## Безопасность на других ТВ

Модуль ничего не пишет во флеш. Хуже всего, если что-то пойдёт не так, — сбой ядра и перезагрузка. После неё модуль загрузится снова, только если остался в `/data/adb/modules/ledctl`. Защита от этого в несколько слоёв:

1. **Ядро другой сборки** не загрузит модуль совсем: не совпадут CRC символов из `__versions`, и ни одна строка кода модуля не выполнится. Номер версии ядра в `vermagic` при включённом MODVERSIONS ядро не сравнивает (`same_magic()` пропускает его): копия с `4.19.117++` загрузилась, а с одним испорченным CRC `printk` — нет (`disagrees about version of symbol printk`). Сравнивается остальная часть `vermagic`: `SMP preempt mod_unload modversions aarch64`.
2. **Смещения не зашиты.** При загрузке модуль дизассемблирует `pwm_backlight_suspend` и `pwm_backlight_resume` работающего ядра. Смещения полей он берёт из инструкций `LDRB/LDRH`, которые загружают аргумент перед каждым вызовом `MDrv_PM_PWM_{Div,Period,DutyCycle,Polarity}_Ex`. Смещение структуры (`bl_get_data`) и флага поддержки он берёт из тех же функций. Отказ, если чего-то не хватает, вызов повторяется, загрузки идут из разных структур, suspend и resume расходятся или размеры полей не те.
3. **Устройство проверяется.** `backlight_device` должен принадлежать именно `pwm_backlight`: `ops->update_status == pwm_backlight_update_status`. Все чтения чужой памяти идут через `probe_kernel_read`, поэтому неверный указатель даёт отказ, а не сбой.
4. **Значения проверяются.** В device tree должно быть включено `led-pwm-control-support`, канал не больше 15, полярности 0 или 1, периоды не нулевые. Иначе модуль отказывается загружаться.
5. **Неудачная установка ничего не оставляет.** Если ядро отказало, приложение удаляет папку модуля, и при следующей загрузке ничего не грузится.

Причину отказа видно на экране и в `dmesg | grep ledctl`.

## Файлы

- `ledctl/ledctl.c`: модуль. Версия остаётся 1.0 до релиза в `main`; приложение замечает новую сборку по контрольным суммам файлов, а не по номеру. Параметры перечислены в шапке файла, все они есть в `/sys/module/ledctl/parameters/`. Там же `info` (найденные смещения и текущие значения) и отладочный `pwm` (`period duty div polarity`).
- `ledctl/magisk/`: `service.sh` (загрузка с `ledctl.conf`), `watch.sh` (сообщает модулю о включении и выключении экрана), `module.prop`, `ledctl.conf` по умолчанию.
- `app/src/main/assets/ledctl/`: то же самое плюс собранный `ledctl.ko`. Приложение кладёт эти файлы в `/data/adb/modules/ledctl`.

## Сборка модуля

Дерево ядра не нужно. Заголовки берутся с самого ТВ, где включён `CONFIG_IKHEADERS`:

```bash
adb shell "su -c 'cp /sys/kernel/kheaders.tar.xz /data/local/tmp/; chmod 644 /data/local/tmp/kheaders.tar.xz'"
```
```bash
adb pull /data/local/tmp/kheaders.tar.xz ledctl/
```

Потом в Linux или WSL нужны clang и ld.lld с поддержкой aarch64. Подходит любой свежий: root не нужен, deb-пакеты `clang-NN`, `lld-NN`, `libclang-cppNN`, `libclang-common-NN-dev` можно распаковать `dpkg -x` в `~/ledko/tc`.

```bash
TC=$HOME/ledko/tc/usr/lib/llvm-21 bash ledctl/build.sh
```

`build.sh` кладёт результат в `ledctl/ledctl.ko` и в `assets`. В kheaders нет MStar-заголовков `mach/memory.h` и `mach/irqs.h`: модулю они не нужны, поэтому вместо них лежат заглушки в `ledctl/stub`.

Для другой сборки ядра нужно обновить `vermagic` и CRC в конце `ledctl.c`. CRC берутся из секции `__versions` штатных модулей `/vendor/lib/modules/*.ko`: `kallsyms_lookup_name`, `printk`, `scnprintf`, `kstrtoint`, `kstrtouint`, `module_layout`. `check_ko.py` сверяет размер `struct module` и смещения `init`/`exit` собранного модуля со штатным.
